Database (Chris)

Topic: Normalized Integration & Privacy (Baseret på Portfolio 1)
The "Difficult" Challenge:
Converting raw IMDB data (Strings) into a strict 3NF Relational Schema.
Solution: Replacing comma-separated lists with Join Tables (title_genre, person_known_for).
The Privacy Model:
Designed a strict separation: Movie Data (Public/Read-only) vs. User Data (Private).
UUID Strategy: All Primary Keys are UUIDs, ensuring we can merge datasets without ID collision.
Result: A scalable foundation that handles complex relations efficiently.

Backend (Chris)

Vi opic: Security & API Composition (Baseret på Portfolio 2 + Final Polish)
The "Interesting" Feature: Stateless Auth:
Implemented JWT (JSON Web Tokens) to secure the API.
Allows a Stateless architecture where every request carries its own identity.
API Orchestration:
The API forces a Clean Architecture.
It aggregates data from multiple repositories into DTOs (Data Transfer Objects).
Example: PersonDetails combines local SQL data + calculated Co-Player stats before sending to Frontend.

Frontend (Chris)

VTopic: Seamless Integration (Baseret på Subproject 3)
The "Clever" Feature: Unified Bookmarks:
Problem: Avoiding duplicate code for Movies vs. Actors.
Solution: A Polymorphic BookmarkButton component handling generic TargetTypes.
External Integration (TMDB):
We use the IMDB nconst (from our DB) to query the TMDB API live.
Why? Provenance + Aesthetics. We keep the reliable data locally, but fetch the beautiful assets remotely.
